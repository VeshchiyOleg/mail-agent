# PLAN.md

План реализации mini-ассистента «по образу Коли» (Java 8 / Maven / JACOB / LLM tool-calling).
Написан до кода. Порядок шагов — это порядок коммитов; внутри каждого шага сначала падающий тест, потом реализация (TDD, red→green).

## Дедлайн

Сдача — **завтра, 2026-08-14** (время пошло с 2026-08-13). Сдаётся вручную письмом с архивом (не ссылкой на репозиторий), лимит вложения — **20 МБ**. Из-за жёсткого срока: не тратим время на вопросы заказчику, которые не блокируют старт кода (LLM-провайдер, доступ к референсу «Коли», точное время слота защиты) — эти вопросы пользователь отправит сам параллельно с разработкой. Приоритет — обязательное ядро (§3 задания), stretch — только если останется время.

## Нюанс среды: разработка на Mac (Apple Silicon), проверка на Windows (Intel)

Влияет на план так:

- **`OutlookMailChannel` физически нельзя запустить/пощупать на Mac** — статический инициализатор JACOB падает вне Windows так же, как на Linux (поэтому и исключается из test-classpath). Реализация должна оставаться максимально тонкой (только COM-вызовы + маппинг в `Msg`), чтобы там было минимум логики, которую негде проверить до Windows-стенда.
- Момент доступа к Windows-стенду для проверки JACOB пока не известен (уточняется отдельно) — план строится на пессимистичном сценарии «доступ только на защите», но шаг 9 (JACOB) сознательно вынесен так, чтобы его можно было безопасно сдвинуть раньше, если доступ появится в процессе.
- С первого коммита фиксируем как обязательные практики (не как «улучшение под конец»): явный `UTF-8` везде (файлы, YAML, логи — дефолтный charset на русской Windows для Java 8 часто `windows-1251`, а не UTF-8, письма кириллические), явная `ZoneId` в `Clock` (не системная зона), никаких хардкод-разделителей путей. Подробности — в CLAUDE.md, раздел «Dev machine vs. grading machine».
- JDK 8 на Apple Silicon — Zulu (Azul) aarch64-сборка, т.к. официальных Oracle/OpenJDK 8 arm64-сборок под macOS нет.

## 0. Скелет проекта (коммит 1)

- `pom.xml`: Java 8, зависимости — okhttp, jackson-databind + jackson-dataformat-yaml (или snakeyaml), jacob 1.20, slf4j-api + logback-classic, junit4.
- `maven-shade-plugin` для fat-jar.
- В `maven-surefire-plugin` — `classpathDependencyExcludes` на `net.sf.jacob-project:jacob`, чтобы `mvn test` не падал на не-Windows (статический инициализатор JACOB вызывает `System.exit`).
- Базовая структура пакетов: `mail`, `llm`, `tools`, `agent`, `store`, `audit`, `config`, `App`.
- `.gitignore` (target/, *.jar, локальные конфиги с секретами).
- Пустой `README.md` с заголовками (заполняется по ходу).
- Локальная настройка: JDK 8 на Mac — Zulu (Azul) aarch64-сборка (`brew install --cask zulu8`, либо вручную). Зафиксировать в README, какой именно JDK использовался, чтобы не путать с системным.
- В `pom.xml` сразу: `<argLine>-Dfile.encoding=UTF-8</argLine>` для surefire; везде в коде, где будет File/Stream I/O, — договорённость использовать `StandardCharsets.UTF_8` явно (проверяется по ходу code review на каждом шаге, а не отдельным поздним шагом).

Проверка: `mvn -q compile` проходит на пустом скелете.

## 1. Конфиг (коммит 2)

- Тест: загрузка `config.yaml` → `AppConfig` (llm.endpoint/model/apiKeyEnv/timeoutMs, agent.maxSteps, store.path, mail.pollSeconds/profile/folder). Невалидный/отсутствующий файл → понятная ошибка, без stacktrace наружу.
- Реализация: `ConfigLoader` на jackson-yaml.
- Секреты — только через `System.getenv(apiKeyEnv)`, никогда не читаются из YAML напрямую.

## 2. Модель письма и MailChannel (коммит 3)

- Тест: контракт `MailChannel` (`fetchUnread()`, `reply(Msg, String)`) через `MockMailChannel`.
- `Msg`: стабильный id (EntryID/Message-ID), from, subject, body, receivedAt.
- `MockMailChannel` хранит письма в памяти/списке — нужен для всех дальнейших тестов, не завязанных на Outlook.

## 3. Seen-store и идемпотентность (коммит 4)

- Тест: одно и то же письмо не обрабатывается дважды; состояние переживает "рестарт" (пересоздание store из того же файла на диске).
- Реализация: `SeenStore` — append/lookup по id письма, backing file (JSON или plain-text, по одной записи на строку).
- Это отдельный тест до появления agent-loop — идемпотентность проверяется на уровне store изолированно.

## 4. LlmClient и мок (коммит 5)

- Тест: `LlmClient.chat(messages, tools)` на моке — детерминированный скрипт ответов (tool_call → потом финальный ответ).
- Интерфейс `LlmClient`; `MockLlmClient` (скриптуемый), `HttpLlmClient` (okhttp, реальный эндпоинт) — HTTP-реализацию можно тестировать отдельно с локальным заглушечным сервером (MockWebServer) или просто оставить непокрытой юнитами и проверить вручную по инструкции из README.
- Сверка с документацией провайдера LLM перед реализацией HTTP-клиента (Context7/офиц. дока — формат messages/tools/response).

## 5. Инструменты (коммит 6)

- Тест на каждый инструмент отдельно, до реализации:
  - `current_datetime()` — с инжектируемым `Clock`, детерминированный результат.
  - `add_reminder(text, dueIso)` — пишет в JSON-стор, тест проверяет запись.
  - `find_items(query)` — тест на поиск по заранее заполненному стору.
- Единый интерфейс `Tool` (name, jsonSchema, execute(args) → result/ошибка).
- `ToolRegistry` — реестр по имени.

## 6. Tool-loop (коммит 7)

- Тест на mock-LLM: сценарий "tool_call → результат инструмента → финальный ответ модели", лимит `maxSteps` останавливает зацикливание.
- Тест на кривой/галлюцинированный tool_call (несуществующий инструмент, невалидные аргументы): loop не падает, возвращает модели структурированную ошибку, корректно завершается.
- Реализация: `AgentLoop` — принимает `LlmClient`, `ToolRegistry`, `maxSteps`.

## 7. Аудит-журнал (коммит 8)

- Тест: запись действий (обработанное письмо, вызовы инструментов) append-only; проверка цепочки хешей (каждая запись содержит хеш предыдущей — по аналогии с `HmacSigner` из «Коли»); подмена записи ломает цепочку — тест это детектирует.
- Реализация: `AuditLog`.

## 8. Сборка агента: mail-loop (коммит 9)

- Тест на `MockMailChannel` + `MockLlmClient`: письмо-вход → ожидаемый ответ-письмо (полный e2e-сценарий без Outlook).
- Тест graceful-фолбэка: LLM insta-фейлит/таймаутит → либо понятное письмо-ответ, либо пропуск + WARN-лог, без исключений наружу.
- Реализация: `MailAgentService` — цикл: `fetchUnread()` → фильтр по `SeenStore` → на каждое письмо `AgentLoop` → `reply()` → отметить seen → аудит-запись.
- Golden-кейсы из §10 задания как отдельные тестовые сценарии:
  1. «Напомни завтра в 10 позвонить Ивану» → `add_reminder`, ответ с датой.
  2. «Что у меня запланировано?» → `find_items`, ответ списком.
  3. «Какое сегодня число?» → `current_datetime`.
  4. Пустое/мусорное письмо → graceful, без падения, без лишних вызовов инструментов.

## 9. OutlookMailChannel через JACOB (коммит 10)

- Реализация `OutlookMailChannel` на COM/JACOB (без юнит-тестов — недетерминируемо и недоступно вне Windows+Outlook). Оборачиваем все COM-вызовы в try/catch → WARN, цикл продолжает работу на следующем письме.
- Класс намеренно тонкий — вся ветвящаяся логика (что делать с письмом, идемпотентность, фолбэки) уже проверена тестами в шагах 2–8 через `MockMailChannel`; здесь остаётся только COM-специфичный код, который негде юнит-тестировать.
- **Проверка — как только появится доступ к Windows-стенду**, независимо от того, на каком шаге плана мы к тому моменту находимся:
  - если доступ появляется раньше (в процессе разработки) — переносим ручную проверку JACOB на этот момент, не дожидаясь завершения шагов 10–12;
  - если доступ только на защите — это единственный прогон вживую, поэтому перед ним готовим короткий чек-лист (реальное письмо в ящик → ассистент отвечает; §9 задания) и по возможности просим 5–10 минут "до" самой защиты на дымовой прогон, чтобы был запас на правку мелких проблем (кодировка, профиль Outlook, путь к DLL на PATH).
- Задокументировать в README, как и когда проводилась проверка (или что она ещё не проводилась — это тоже важно указать честно, а не притворяться, что всё проверено).

## 10. Структурные логи и маскирование ПДн (коммит 11)

- Провести по всей кодовой базе: event-keys (`agent_mail_seen`, `agent_tool_call tool=...`, `llm_failed ...`), проверить что нигде не логируется тело письма/ПДн в открытом виде.
- Тест (где возможно): логгер-аппендер в памяти + assert, что в логах нет чувствительной строки из тестового письма.

## 11. main/App и запуск (коммит 12)

- `App.main`: загрузка конфига → сборка зависимостей (DI руками, без фреймворка) → poll-loop с `mail.pollSeconds`.
- Проверка на Mac: `mvn package` → fat-jar, `java -jar target/*.jar` стартует и логирует старт (на машине без Outlook — должен упасть по понятной причине инициализации COM, но не на этапе class-loading остальной логики; либо приложение просто не запускает OutlookMailChannel без Windows — уточнить поведение при ручной проверке).
- Проверка на Windows (при первой возможности, см. шаг 9): тот же fat-jar, собранный на Mac, реально запускается под Java 8 на Windows-стенде без пересборки — байткод платформонезависим, но это должно быть подтверждено фактом, а не предположением. Заодно на этом прогоне проверяется кодировка (кириллица в конфиге/логах/ответах не превращается в кракозябры) и часовой пояс `current_datetime()`.
